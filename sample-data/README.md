# Sample Data: Synthetic Authentication and Access Log

**FICTIONAL SIMULATION.** Everything in this folder is invented.

| File | What it is |
|------|-----------|
| `auth_events.csv` | 166 synthetic authentication and record-access events for the fictional AureliaCare Connect platform, covering 20 to 21 October 2026 |
| `review_auth_events.py` | A small helper script (Python standard library only) that applies six simple review rules to the CSV |
| `02-log-review-exercise.md` | The exercise: how to review the events and what to produce |
| `03-review-worksheet.md` | Your worksheet for recording what you executed, observed and concluded |

## Honesty statement

- The events were **generated by the author** with a script. They are not captured from any real system.
- IP addresses come from ranges reserved for documentation (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24). They do not identify real hosts.
- User identifiers (for example `p.synth017`) and patient identifiers (for example `PT-300`) are invented.
- This exercise is **not SIEM experience**. A SIEM (Security Information and Event Management platform) collects logs from many systems at scale and runs detection rules continuously. This exercise is a small, manual, desk-based log review.

## Column dictionary

| Column | Meaning |
|--------|---------|
| event_id | Unique number for the event |
| timestamp_utc | Time in UTC (Coordinated Universal Time) |
| user_id | Synthetic account name. Prefix `p.` patient, `c.` clinician, `s.` support, `a.` cloud administrator |
| role | Role of the account (R-01 patient, R-02 clinician, R-04 support, R-05 cloud admin) |
| source_ip | Synthetic source address |
| country | Two-letter country code attached to the source address |
| event_type | `login` or `record_view` |
| result | `success` or `failure` |
| mfa_result | `success`, `denied`, `not_enrolled`, or `n/a` |
| resource | Patient record viewed (for `record_view`) |
| patient_assigned | `Y` if the patient is assigned to the viewer, `N` if not, `n/a` where it does not apply. For patients, `Y` means their own record |
| ticket_ref | Support ticket reference, where one was recorded |
